## 部署前准备

保留旧 `.env` 与旧交易记录。新版本构造参数改变，需要新地址。资金、商户、保证金、累计硬上限 `TOTAL_SPEND_LIMIT_WEI` 和费用值由部署者确定，`.env.example` 中金额只是测试示例。累计硬上限不能通过充值或修改授权重置。

Foundry 版本本次为 1.7.1，Solidity 0.8.35；Node 为 22.22.2。已有库位于 `lib/`。Reactive 库本地提交为 `3ade0dcf1d27e67e5783ef807e73a1b9e0c0cce8`，不自动更新依赖。

把模板中的非空配置写入 `.env`，或设置为进程环境变量。下面 PowerShell 命令使用 `$env:...`，因此相应变量必须在当前终端设置；Foundry 自动读取 `.env` 不等于 PowerShell 也读取了它。私钥使用 `cast wallet import <账户名> --interactive` 保存为加密账户；不要在命令里粘贴明文私钥。

```powershell
$env:SEPOLIA_RPC = 'https://ethereum-sepolia-rpc.publicnode.com'
$env:LASNA_RPC = 'https://lasna-rpc.rnk.dev'
$env:CAST_ACCOUNT = '你的加密账户名'
# 另行设置 MERCHANT_ADDR、MINIMUM_BOND_WEI、费用值等模板配置
cast chain-id --rpc-url $env:SEPOLIA_RPC
cast chain-id --rpc-url $env:LASNA_RPC
cast code 0x8888888888888888888888888888888888888888 --rpc-url $env:LASNA_RPC
cast code 0xAa14d9Cd0f788Ca23d11805986C1d8bd035D23b4 --rpc-url $env:SEPOLIA_RPC
```

期望链 ID 分别为 11155111、5318007，代码不能为 `0x`。官方网络表在 2026-11-23 列出的 Sepolia Callback Proxy 是上述地址；广播前再次核对 [官方网络表](https://dev.reactive.network/origins-and-destinations)。不能把“任意地址有代码”视为正确代理的证明。

## 分四步部署

先运行不带 `--broadcast` 的模拟。核对地址、费用和账户后，由部署者明确添加 `--broadcast` 广播。四步使用同一部署账户。

```powershell
# 1. Sepolia：Registry、Capability、Vault、Executor
forge script script/Deploy.s.sol:DeployCore --rpc-url $env:SEPOLIA_RPC --account $env:CAST_ACCOUNT
# 2. 将第一步真实广播输出的 EXECUTOR_ADDR 写入环境，然后部署 Reactive
forge script script/Deploy.s.sol:DeployReactive --rpc-url $env:LASNA_RPC --account $env:CAST_ACCOUNT
# 3. 写入真实 SENTINEL_ADDR，回 Sepolia 部署回调并配置角色
forge script script/Deploy.s.sol:DeployCallback --rpc-url $env:SEPOLIA_RPC --account $env:CAST_ACCOUNT
# 4. 写入真实 CALLBACK_ADDR，在 Reactive 上设置目标地址
forge script script/Deploy.s.sol:ConnectReactive --rpc-url $env:LASNA_RPC --account $env:CAST_ACCOUNT
```

模拟输出的地址不能代替已确认广播地址。每一步记录交易哈希、区块号和实际地址。`DeployCallback` 会配置 Registry.operator、Capability.revoker、Vault.slasher、Executor.resolver。部分广播失败时检查交易回执并恢复剩余配置，不要盲目重跑整套部署或改变一次性角色。

检查连接：

```powershell
cast call $env:SENTINEL_ADDR 'recipient()(address)' --rpc-url $env:LASNA_RPC
cast call $env:EXECUTOR_ADDR 'resolver()(address)' --rpc-url $env:SEPOLIA_RPC
cast call $env:VAULT_ADDR 'executor()(address)' --rpc-url $env:SEPOLIA_RPC
cast call $env:VAULT_ADDR 'slasher()(address)' --rpc-url $env:SEPOLIA_RPC
cast call $env:REGISTRY_ADDR 'operator()(address)' --rpc-url $env:SEPOLIA_RPC
cast call $env:CAPABILITY_ADDR 'revoker()(address)' --rpc-url $env:SEPOLIA_RPC
```

其中 `VAULT_ADDR`、`REGISTRY_ADDR`、`CAPABILITY_ADDR` 来自第一步输出。不要把另一份同名项目目录中的地址混进来。

## 演示顺序

1. 项目方 `registerAgent(address,string)` 登记 Agent；`grantCapability(address,bytes32,uint256,uint256,string)` 授权。参数依次是 Agent、capId、单笔最大 wei、未来到期时间、策略标签。策略标签仅留档。
2. 项目方给 Executor 调用 `fund()` 并附 ETH。Agent 用自己的账户给 Vault 调用 `stake()`，金额至少为 `minimumBond()`。项目预算、保证金和回调费用是三份不同资金。
3. Agent 调用 `executeOrder(bytes32,uint256)`，金额等于或低于限额。核对 `availableBudget` 减少、`merchantCredit` 增加。商户用自己的账户调用 `claimPayment()`，核对收款交易。
4. Agent 请求超过限额的订单。记录 `ActionReceipt` 和 `RiskAlert` 的同一个 `receiptId`。此时预算和商户债权不变，`pendingReceipt(agent)` 非零、`locked(agent)` 为 true。
5. 在回调落地前尝试 `withdraw()` 和再次下单，两者都应回滚。等待 Reactive 的 `AlertObserved` 与 `Dispatched`，再等待 Sepolia 的 `DispositionExecuted`。
6. 核对该回执 `settled=true`、Callback.processed=true、Agent 状态为 Revoked、能力 active=false、stake=0、forfeited 增加。项目方 `claimForfeiture(address)` 可领取罚没；调用前后保存余额或事件，不能在领取后仍要求 forfeited 非零。
7. 再次下单应被拒绝。项目方可用 `withdrawBudget(address,uint256)` 收回未花预算，不能取走已经记给商户的债权。

只看 `Dispatched` 不足以证明完成；必须核对目标链最终状态。示例只说明 ABI，不内置私钥或自动给旧地址发送交易。

## AI 与失败演示

新部署默认 `aiMode=false`。要展示解释，在发送违规请求前由 owner 调用 `setAiMode(true)`，启动 `node scripts/ai-verdict.js --submit`。没有模型 key 时会明确显示 rules，不作为 AI 调用证据。

停掉服务后，等待 `VERDICT_TIMEOUT()`（300 秒），任何账户可调用 `dispatchExpired(receiptId)`。时间过去不会自行发送交易，演示中要保留这笔兜底调用。

如果系统拒绝回调请求，`DispatchFailed` 与仍然 open 的告警保留；补足费用或修复服务后，调用 `dispatchExpired` 或重新提交 verdict。AI 模式的超时限制仍适用。

若请求已成功但目标交付失败，修复角色或补足 Callback 费用后，owner 在 `RETRY_DELAY()`（60 秒）后调用 `retryDispatch(receiptId)`。目标回调按回执去重，重复交付不会重复罚没。没有自动重试次数上限，owner 需要核对最终状态，避免浪费费用。
