# AgentSentinel 验证与边界

验证日期：2026-11-25（Foundry）；脚本测试记录为 2026-11-23。

## 初版观察

执行 `forge test -vv`，输出 `No tests found in project!`。源代码检查发现：

| 观察 | 影响 | 本次处理 |
| --- | --- | --- |
| executeOrder 只发事件 | 不能证明订单执行或资金约束 | 增加项目预算、固定商户债权和提款 |
| Vault.withdraw 不检查待处置 | 违规后可在异步回调前移走保证金 | 超额请求同交易锁定，禁止提款和继续下单 |
| slash 清零账本但资金留在金库 | 罚没去向不完整 | forfeited 独立计账，项目方显式领取 |
| AI 可把超额判成 0/1 | 硬规则可被绕过 | 本流程仅接受 L3；其他等级拒绝 |
| react 不检查源链 ID、重复覆盖 alert | 错链或重放输入可污染状态 | 精确来源过滤、编码检查、seen 去重 |
| 回调不保存处理标志 | 重投可重复执行，或在已撤权时整体失败 | 回执校验、processed 去重、撤权幂等 |
| Agent 状态能恢复 None 或从 Revoked 恢复 | 不符合终止语义 | 禁止擦除注册和恢复已吊销身份 |
| 脚本先标记 processed 再发送，失败不恢复 | 临时故障可永久丢失任务 | 持久化待办，成功后移除，失败退避重试 |
| execSync 拼接模型理由和私钥 | 输入进入 shell，错误输出可能带敏感参数 | execFileSync 参数数组、加密账户、清理错误输出 |
| 没有实际模型调用也称模拟 LLM | 不能证明 AI 参与 | 明确标记 rules 与 dashscope |

## 状态与守卫核对

使用 semantic-guard-analysis 的状态写入与权限核对方法，逐个检查入口。这里是人工检查与回归测试，不是完整形式化审计或自动 AST 分析报告。

| 状态 | 修改入口 | 约束 |
| --- | --- | --- |
| Agent.status | registerAgent / setStatus | owner 或授权 operator；Revoked 终止 |
| Capability.active | grant / revoke | owner 或 revoker；撤权幂等；执行时查到期时间 |
| stakes / totalStaked | stake / withdraw / slash | 本人出入金；locked 禁止提款；slash 仅 slasher |
| locked | lock / slash | executor 锁定，slasher 完成处置；公众无解锁入口 |
| forfeited | slash / claimForfeiture | 罚没入账，owner 领取；转账前更新账本 |
| availableBudget / merchantCredit | fund / execute / withdrawBudget / claimPayment | owner 出入未花预算；商户仅领自己的债权 |
| pendingReceipt / settled | execute / settle | 同步登记，resolver 结算；待处置期间拒绝新订单 |
| seen / alerts | react / submit / dispatchExpired | 系统消息来源验证；AI 不能降级；超时兜底公开 |
| processed | onSentinelVerdict | 官方代理 + Sentinel 双鉴权 + 源链回执匹配 |

## 实际验证结果

`forge test -vv`：28 项通过、0 失败。其中两个 fuzz 测试各运行 256 组输入：单笔额度边界，以及每组 24 步的下单、提款、付款、罚没序列。新增累计总额、防拆单/充值/换授权绕过、跨 Agent 共享总额和空预算充值恢复测试；截图见 `evidence/forge-test.jpg`。

`node --test scripts/ai-verdict.test.js`：12 项通过、0 失败。检查 uint256 精度、事件来源、跨链证据匹配、非法 verdict、模型失败回退、模型来源标签、shell 参数隔离、失败任务重试和配置验证。另用本地 HTTP RPC 替身启动真实 CLI，确认只扫描已确认区块、重启不重复处理，以及 RPC 失败后待办落盘并在下次启动恢复。这不是公网 RPC 或真实模型集成测试。

`forge build --sizes`：构建成功。六个业务合约运行时代码均低于 24,576 字节。编译器无警告；Forge lint 对到期、超时和重试窗口中的 `block.timestamp` 比较给出提示。这些时间值只用于秒级窗口，不用作随机数或严格现实时间证明。

关键用例：

| 用例 | 验证内容 |
| --- | --- |
| testEndToEndFromActualEventAndMerchantPayment | 实际发出日志、商户收款、锁款、回调、罚没领取、后续订单拒绝 |
| testPendingBlocksWithdrawalAndFurtherOrders | 异步窗口期间提款和新订单都被拒绝 |
| testWithdrawBeforeRequestCannotEvadeBond | 提前提款后无法继续执行订单 |
| testDuplicateRiskAndCallbackAreIdempotent | 重复消息不会重复请求或重复罚没 |
| testCallbackCannotPunishValidOrder | 即使可信代理发出错误 payload，也不能罚合法订单 |
| testAiCannotDowngradeAndTimeoutFallbackWorks | 模型不能放过硬违规；超时可由其他账户触发 |
| testRulesModeRequestFailureKeepsObservationForRecovery | 系统请求失败不会丢失已观察告警 |
| testCallbackFailureRollsBackAllEffectsAndCanRetry | 某一步失败，撤权和罚没一起回滚；修复后可重试 |
| testSponsorCanRecoverOnlyUnspentBudget | 项目方不能取走已经记给商户的债权 |

随机序列核对：Executor 余额等于未花预算加商户债权；Vault 余额等于未罚保证金加未领取罚没。在强制发送 ETH 的情况下应使用余额大于等于账面负债，本次测试没有模拟强制转入。

## 未证明和剩余风险

- 没有重新部署 Sepolia/Lasna，没有真实交付延迟、费用、RPC 长时间运行或模型服务成功调用的数据。模拟系统接受请求不证明真实网络接受请求。
- 没有独立第三方审计、形式化验证或正式保险定价。
- 单笔额度由 Capability 控制，所有 Agent 共用 Executor 部署时固定的累计总上限，充值不能绕过。仍没有每 Agent 独立累计额度、限频或分周期预算。当前只有一个固定商户，不能把这个模型描述为通用资产防盗。
- 项目方能改授权额度和有效期，也能更换 Registry.operator / Capability.revoker。错误或恶意管理员配置可能影响处分和活性；当前没有多签治理或延时生效。
- 全额罚没针对被拦截请求，实际损失可能为零。没有申诉、比例罚款或用户签署策略版本的机制。
- Reactive 网络或回调长期不可用会造成保证金持续锁定。源事件如果从未被网络观察，不能靠 `dispatchExpired` 补造观测。当前选择保守锁定，没有管理员任意解锁出口。
- AI 超时需要有人调用兜底，目标回调重试需要 owner。请求成功不代表目标处置完成，不能仅凭 Dispatched 宣布成功。
- `.state` 保存游标和解释，异常进程退出可能留下锁文件；人工确认进程退出后再清理。源链深度重组需要人工核对，当前不会自动回滚已经发送的处分。
- `policyHash` 是字符串标签，未校验真实文件哈希；DID 是项目方登记字符串，不证明现实身份，也不是标准身份协议集成。
- 旧地址与本版不兼容。原文件已在修改前压缩备份，旧部署交易文件保留，不能把它们当成本版实网验证。
