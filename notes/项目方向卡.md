# 项目方向卡

记录日期：2026-11-25

## 一句话

AgentSentinel 监听 Sepolia 上 Agent 的采购请求；当请求金额超过授权上限时拒绝付款并保存回执，再由 Reactive 在 Lasna 接收风险事件、验证链上证据，并通过回调撤销授权、锁定并罚没保证金、吊销 Agent 身份。

## 赛道

赛道 3：Reactive Meets AI。

AI 在运行时读取已记录的超额证据，生成供人工查看的解释。它不决定是否违规，也不能降低或扩大处置等级；最终动作由合约按 `amount > maxSpend` 的确定性规则执行。无 API key 时使用规则说明。本地测试验证合约流程，没有调用真实模型。

项目不主张需要 1 秒级反应，因此不选赛道 1。Reactive 用于验证事件驱动的异步跨链处置，增加费用和交付延迟；对于仅在 Sepolia 的资产，单链合约直接撤权更简单。

## 用户与场景

目标用户假设是给 Agent 分配小额链上采购预算的项目方。项目方需要限定可操作的 Agent、固定商户、单笔额度和累计支出；超额操作要当场阻止，并保留可以核对的证据。

现在可以用钱包限额、单链 Guard 或链下监听器实现部分约束。当前原型只支持进入 `SentinelExecutor` 的 ETH 订单和固定商户，不接管任意钱包或 DEX。目标用户假设还没有经过访谈，仓库中没有真实采用或付费数据。

## 最小 Demo

1. 项目方登记 Agent、授权单笔额度并给 Executor 预算；Agent 存入保证金。
2. 发起额度内订单，核对预算扣减和商户债权；领取商户款是另一笔交易。
3. 发起超额订单，核对付款被拒绝、回执被保存且保证金锁定。
4. Reactive 接收 `RiskAlert`，按回执验证后请求目标链回调；回调撤权、罚没保证金并吊销身份。
5. 重复事件不重复处置；单笔或累计额度超限被拒绝；回调失败后按 README 的步骤重试。

Foundry 本地测试覆盖上述流程。当前最新版本尚未重新部署测试网；旧版本交易不能用来证明这一版已部署。
