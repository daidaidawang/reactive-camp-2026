# AgentSentinel：受限付款与可核对的跨链处置

Demo Day 演示稿｜目标时长 2 分 50 秒｜赛道 3：Reactive Meets AI

## 1. 问题与承诺｜0:00–0:25

**给 Agent 预算，怎样限制它能花多少，并在越权后留下可核对的处置记录？**

AgentSentinel 为 Agent 登记身份、限定固定商户和单笔额度。额度内付款可执行；超额请求被同步拒绝并保存证据。

讲解：这是一个受限采购原型，不接管任意钱包或 DeFi 交易。

## 2. 事件如何走完｜0:25–0:55

```text
Sepolia Executor → RiskAlert → Lasna Reactive → Sepolia Callback
      │                 │              │                  │
  检查/记回执       超额证据事件    核验证据/去重      撤权/锁款/处置
```

AI 输入是链上已确认的 Agent、商户、金额、额度和回执；输出是供人工查看的解释。`amount > maxSpend` 才是违规条件，AI 不能降级或改变处分。

讲解：真实模型尚未在本次运行中调用；没有真实模型证据时，清楚标注规则模式。

## 3. 正常与超额｜0:55–1:35

**正常请求：** 额度内 ETH 从 Executor 预算记为固定商户债权；商户另行领取。  
**超额请求：** 付款不发生，保存原始回执并锁定保证金，等待后续处置。

讲解时展示两笔源链交易与状态变化。不要把测试输出或模拟账户描述成公开链交易。

## 4. Reactive 与回调证据｜1:35–2:20

| Callback / 最终处置 | Sepolia | 待新版部署与演示后填写 |

讲解：只有核对目标 Callback `processed=true` 和源链回执 `settled=true` 才算完成；Reactive 已请求回调不等于目标处置成功。

## 5. 保护、恢复与边界｜2:20–2:50

- 来源、Executor、topic 和超额条件不符时不触发；相同事件只处理一次。
- 单笔额度和全局累计支出上限共同限制资金。
- 费用或目标回调失败时保留待办/锁定状态，修复后按 README 流程重试。
- 本地验证：Foundry 34 项通过，Node.js 12 项通过；这是替身环境测试，不是公开链证明。

结尾：展示的是局部同步拦截、可审查回执和异步处置。测试网证据补齐前，不声称已完成真实跨链演示或生产可用。
