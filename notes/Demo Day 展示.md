## 录制前待完成

当前版本尚无新部署地址、三段链上交易证据或视频。这些是演示执行和 Reactive 集成的核心材料，不能由幻灯片替代。按[部署与演示步骤](../agentsentinel/docs/部署与演示.md)使用最新代码重新部署；用同一回执 ID 核验 Sepolia 源事件、Lasna `react()` 和 Sepolia 回调完成状态后再录屏。视频需少于 3 分钟；上传前复核黑客松官方表单限制。

录屏应显示浏览器交易详情、对应事件和状态变化，并说明真实模型是否调用。本次未调用真实 LLM，应准确描述为“模型路径经本地测试，实际演示使用规则模式”。

## 两分钟问答备忘

- 为什么用 Reactive：展示独立事件处理和异步目标链回调；对当前仅在 Sepolia 的资产而言，单链撤权更简单，Reactive 不是必要条件。
- AI 做什么：只根据结构化超额证据写解释，不做违规判断；规则和合约状态决定处置。
- 资金是否安全：目前是测试网原型。资产仅限进入 Executor 的 ETH 和固定商户；未审计，不接管任意钱包、Safe、DEX 或通用跨链资产。
- 回调失败怎么办：处置交易原子回滚，保证金仍锁定；修复费用或配置后按 README 流程重试，最终检查 `processed` 和 `settled`。
- 如何证明实测：展示同一回执 ID 对应的三条浏览器交易和最终状态；Foundry 测试只证明本地替身下的行为。
