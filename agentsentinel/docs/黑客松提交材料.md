## 测试结果

运行 `forge test -vv`，34 项通过，0 项失败：AgentSentinel 28 项、Bounded Cron 6 项。两个 fuzz 测试各运行 256 组输入。现有截图只覆盖主套件，不能当作 34 项全套截图。

覆盖内容：

- 来源链、Executor、topic 和超额条件不匹配时忽略事件；只接受授权回调。
- 相同告警重复到达时只请求一次处置；相同回调重放不会重复罚没。
- 正常单笔额度内的订单可以付款；超出单笔额度的请求会被拦截并锁定保证金。
- 累计支出上限由所有 Agent 共用；拆单、充值、领取款项和更换授权都不能重置上限。
- 预算用完后订单失败；总支出还未到上限时，补充预算后可以继续执行。

## 失败模式

- 事件来源或金额条件不符合：Reactive 合约忽略事件，不发送处置回调。
- 单笔额度或累计支出上限触发：订单不付款、不增加商户债权；超额请求留下回执并锁住保证金。累计上限触发时不会创建违规告警。
- 项目预算不足：交易回滚。项目方可以调用 `fund()` 充值；充值不会重置累计支出上限。
- Reactive 或 Callback 费用不足并产生欠费：网络会暂停对应合约。使用系统合约或目标链代理的 `depositTo(address)` 为指定合约补充费用并清偿欠费，再检查 `debt(address) == 0`。只向合约地址转币不保证恢复。
- Reactive 请求回调失败：告警仍保持 open。修复费用或服务后，调用 `dispatchExpired(receiptId)` 重试；AI 模式需等待 300 秒。
- 目标链回调失败：撤权、罚没和回执结算在同一交易中回滚，保证金继续锁定。修复原因后，等待 60 秒，再由 owner 调用 `retryDispatch(receiptId)`。
- `Dispatched` 只表示 Reactive 接受了回调请求。需检查目标合约 `processed(receiptId)` 和源链回执 `settled`，确认处置实际完成。

以上失败路径在 Foundry 测试中由本地系统和代理替身验证；这次没有部署测试网。Node.js 解释服务另有 12 项测试通过，未调用真实 LLM。
