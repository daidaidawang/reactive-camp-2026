# Day 3（11/18）打卡：第一个 Reactive 合约

## 目标

基于 omni 分支 Xfers.sol 示例，在 Lasna 部署监控合约，订阅 Sepolia ERC-20 Transfer，成功触发至少一次 react()。

## 实现

- 自部署测试代币 MockERC20（CTT）到 Sepolia，订阅它的 Transfer（topic1-3 用 REACTIVE_IGNORE）。
- 附加过滤：单笔 ≥ 5 CTT 才计数（react() 内 return 过滤，不用 revert）。
- 上限 3 次，达到后自动取消订阅（unsubscribe 六参数与 subscribe 严格一致）。
- payable 构造函数 + 部署时 `--value 0.05ether` 预存费用。

## 验证结果

- Sepolia 上 1、2 CTT 的转账低于阈值，不计数；10、7 CTT 和后补的一笔 5 CTT 命中阈值。
- 第 3 次命中对应 `Matched` 事件 amount = `5e18`、count = 3；`lastTxHash` 与源链交易哈希 `0x26037056d061a72af9855112e9dd1c5bff7bbda0f056d8e12ce3ddd3639a3827` 一致。
- 最终链上状态：`_matchedCount() = 3`、`_limit() = 0`、SYSTEM `debt() = 0`；查询当前 Reactive filter index，已无 CTT 的 Transfer 订阅，自动退订完成。
- 最后一次 `react()` 的 [Reactscan 交易](https://lasna-omni.reactscan.net/tx/0x51f23ac799e83c3a90257f904db7a324cd3d2a25dce9013acce0e8006c8050a4) 位于 Lasna 区块 8642323。

## 欠费恢复记录

- 排查时发现合约曾有 `0.0136774 lREACT` debt，合约余额约 `0.0084838 lREACT`，因此 Reactive 暂停投递；欠费期间发出的一笔 5 CTT 转账未触发 `react()`。
- 通过 Sepolia faucet 的 `request(address)` 为监控合约补入 10.5 lREACT（支付 0.1 Sepolia ETH），随后调用 Lasna SYSTEM `depositTo(address)` 并存入 0.1 lREACT：debt 清零，剩余约 `0.0863226 lREACT` 进入 reserves。
- 欠费清除后重新发出 5 CTT 转账，成功完成第 3 次命中并自动退订。这个过程也验证了直接给合约充值与向 SYSTEM `depositTo` 的差异：前者只增加合约余额，不会自动清偿 debt。

## 踩坑记录

1. `@reactive/` remapping 必须指向 lib 仓库根目录，不是 `src/`：
   `@reactive/=lib/reactive-lib-omni/`
2. 新版 forge create 需要 `--broadcast` 才真正上链。
3. Foundry public 变量 `_limit` 的 getter 是 `_limit()`（带下划线），不是 `limit()`。
4. reactive 交易的 from 是验证者节点地址（如 `0x038E06...`），to 是 SYSTEM 合约——不是你的钱包，这是设计如此（费用 kickback 给 tx.origin 验证者）。Reactscan 显示层会把有效目的地显示为你的合约。
5. Lasna 的 eth_call 对不存在的 getter 返回空 revert，注意区分函数名写错和网络问题。
