# 场景小实验：定时任务或动态订阅（二选一）

记录日期：2026-11-25

## 选择

选择 A：定时执行。订阅 Lasna 的 `Cron100`，每次收到定时事件就向 Sepolia 的回调合约发送一个编号和源区块号；最多执行两次后自动退订。`Cron100` 每 100 个 Lasna 区块触发一次，文档给出的时间约为两分钟，实际时间随出块变化。

这个小实验单独作为边界明确的演示，不把周期性心跳并入 AgentSentinel 的资金处置路径。当前业务没有已验证的秒级定时需求。

## 保护

- Reactive 合约仅接受 SYSTEM 传入、来自 Lasna Cron 专用地址且 topic0 精确匹配 `Cron100` 的日志；同一来源日志按区块哈希、交易哈希和日志序号去重。
- `CRON_MAX_RUNS` 在部署时固定，必须大于零；达到上限后合约主动取消订阅。owner 可提前停止，停止后不能恢复或提高次数。
- 回调合约同时校验 Callback Proxy 和 Reactive 合约地址；只接受 `1..maxRuns` 的编号，并按编号去重。
- 每次 Cron 和每次目标链回调都会产生费用。次数上限限制最多的触发和回调数，但不保证费用不会耗尽；为 Reactive 和目标链回调分别准备小额费用并监控余额、欠费状态。
