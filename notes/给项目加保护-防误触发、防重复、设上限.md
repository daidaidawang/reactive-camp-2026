## 验证结果

运行 `forge test -vv`，28 项通过、0 项失败；两个 fuzz 测试各运行 256 组输入。

- 只接受授权的源链、Executor 和事件；非超额事件不触发处置。
- Sentinel 和目标回调都按回执去重，同一事件重复到达不会重复请求或罚没。
- 合法的单笔额度内请求正常付款；超额请求不付款并锁定保证金。
- 所有 Agent 共用累计支出上限；拆单、充值、领取商户款或更换授权不会重置上限。

## 失败模式

- 事件来源或条件不匹配：忽略事件，不发送处置回调。
- 超过单笔额度：阻止订单，保留回执并锁定保证金；不会增加商户债权。
- 达到累计支出上限：拒绝后续付款；充值不会重置计数。
- 项目预算不足：订单交易回滚。项目方可调用 `fund()` 充值；若累计上限尚未用完，可以继续执行。
- Reactive 或 Callback 费用不足并产生欠费：对应网络服务暂停。通过 Reactive 系统合约或目标链 Callback Proxy 的 `depositTo(address)` 为指定合约清欠并充值，再检查 `debt(address) == 0`。只给合约地址转账不能保证恢复。
- Reactive 回调请求失败：告警保持 open；修复费用或服务后调用 `dispatchExpired(receiptId)`。AI 模式要等 300 秒。
- 目标链回调失败：撤权、罚没和结算整体回滚，保证金继续锁定；修复后等待 60 秒，由 owner 调用 `retryDispatch(receiptId)`。
- `Dispatched` 只说明回调请求已提交。检查目标端 `processed(receiptId)` 和源链 `settled` 状态，确认处置完成。

测试使用 Foundry 本地合约、Reactive 系统和 Callback Proxy 替身；没有在本次验证中部署测试网。

这份测试代码和截图已随最新 `agentsentinel` 版本一起放入仓库。测试中的 Reactive SYSTEM 和 Callback Proxy 为本地替身，不是测试网部署记录。
