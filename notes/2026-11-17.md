# Day 2（11/17）打卡：源链、目标链与费用模型

## 双侧付费模型（Omni 版）

- **Reactive 侧**：SYSTEM 合约（`0x8888...8888`）对执行 `react()` 收费，用 REACT/lREACT。
- **目标链侧**：callback proxy 对送达回调收费，用目标链原生币（ETH/BNB…），不是 REACT。

## 三个关键数字

| 值 | 含义 |
|---|---|
| Balance | 合约自己的余额 |
| Reserves | 预存在系统合约/proxy 里的费用储备 |
| Debt | 欠费 |

- 收费先扣 Reserves，不够才挂 Debt；充值先还 Debt 再转 Reserves。
- **任何 Debt > 0 都会停机**：系统不再调用 react()，proxy 不再投递回调（静默失败，不报错）。

## 费用公式

fee = p_base × C × (g_used + K)，K 默认 100,000 gas（附加费），C 默认 1000。
实测：我们的 react() 单笔费用 ≈ 0.0138 lREACT。

## 充值方式

1. `SYSTEM.depositTo(合约地址)` —— 预存 reserves（推荐，第三方也能救活欠款合约）
2. 直接转账给合约 + 合约实现 `coverDebt()` 暴露还款
3. 部署时 payable 构造函数 + `--value`

## 何时合约会停止执行（本日最重要结论）

- Debt > 0（任何金额）
- 合约余额与 reserves 都耗尽
- 过滤条件写成了 revert：**revert 的 react() 依然被全额收费**（`ReactiveContractReverted`），反复 revert = 烧钱停机 → 过滤一律用 return
