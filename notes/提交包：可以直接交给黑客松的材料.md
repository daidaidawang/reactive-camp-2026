## 项目介绍（可直接用于报名表）

AgentSentinel 是一个给链上 Agent 设置受限采购权限的原型。项目方登记 Agent，为其授权固定商户和单笔 ETH 支出上限，并把预算存入 Executor。正常请求在链上记为商户可领取的付款债权；超过授权额度的请求会在源链同步拒绝，不向商户付款，同时保存 ActionReceipt、锁定 Agent 保证金并发出风险事件。

Reactive 在 Lasna 监听风险事件，检查事件来源、Executor、topic 和回执证据，并通过官方 Callback Proxy 请求 Sepolia 上的目标合约。目标合约会再次验证代理地址、Sentinel 地址和源链回执，然后撤销能力、吊销 Agent、罚没锁定保证金并结算回执。重复事件不会重复处置。回调失败时，处置交易原子回滚，保证金保持锁定，修复后可按延迟重试。

AI 的运行时输入是链上已核对的 Agent、商户、请求金额、授权上限和回执；输出是供人阅读的自然语言解释。是否违规由 `amount > maxSpend` 的确定性规则判断。AI 不能放过超额请求，也不能调整罚没额度。本地测试覆盖规则、AI 输入校验和失败回退；目前没有真实模型调用记录。

当前范围是测试网原型：只处理进入 Executor 的 ETH 和一个固定商户，不接管任意钱包、Safe、DEX 或通用跨链资产。项目验证的是“源链先阻止付款、Reactive 异步送达处置、目标链核验后执行”的链路，不声称已经证明生产安全或多链权限同步。

## 本地复现与验证结果

环境版本：Foundry 1.7.1、Solidity 0.8.35、Node.js 22.22.2。依赖已随仓库提供，不需 npm 安装。Windows PowerShell 从仓库根目录运行：

```powershell
cd agentsentinel
forge test -vv
node --test scripts/ai-verdict.test.js
```

2026-11-25 实际运行结果：Foundry 34 passed、0 failed、0 skipped，其中 AgentSentinel 28 项、Bounded Cron 6 项；两个 fuzz 用例各运行 256 组。Node.js 12 passed、0 failed。[`forge test -vv` 完整输出](../agentsentinel/submission/evidence/forge-test-2026-11-25.txt)与[终端截图](../agentsentinel/submission/screenshots/command-tests.png)都保存，退出码为 0。

测试包含来源链与日志过滤、代理鉴权、重复事件幂等、额度内付款、单笔和全局累计上限、预算用尽及补充、回调失败原子回滚与重试、AI 不得降低确定性违规以及超时兜底。测试环境里的 Reactive SYSTEM 和 Callback Proxy 是本地替身；真实链上交付另由下面三笔交易与状态读回证明。
